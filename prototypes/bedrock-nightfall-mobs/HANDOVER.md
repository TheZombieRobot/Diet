## What the owner asked for

- A separate add-on from Hearts & Lives (which permanently removes a heart per death - so nothing here may be an
  unavoidable death).
- Three night mobs from the concept posters: Gloomhound, Thornskulk, Horde Stalker (with a 20-30 zombie horde of
  weak, ordinary-speed zombies).
- "A little bit harder than the standard mobs, but not super hard", with correct, explainable maths.
- A difficulty changer in a craftable book that players also receive at the start.
- Each mob can be switched on or off, chosen at the start of a world.
- Played by children; Windows hosts, PS5 joins (possibly split-screen). Retail stable Bedrock only, no experimental
  toggles. Few words on screen, no special Unicode glyphs in forms.

## Decisions made (and why)

- **All numbers live in `src/scripts/balance.js`.** The build generates entity files and `docs/BALANCE.md` from it.
- **Two difficulty layers.** Minecraft's world difficulty scales melee damage as for vanilla mobs; the Nightfall
  Guide setting scales health, base hit and horde size. They are deliberately not linked (linking would double-count).
- **Mobs carry four stat sets** (component groups). The script picks one on spawn/load via an entity event.
- **Toggles are enforced in script** (remove on spawn/load) because spawn rules are static files.
- **Horde loot is a fixed budget** handed to random members at spawn (one item each), dropped only for player kills.
- **Nothing vanilla is overridden**, especially not `player.json` (Hearts & Lives owns it). This is why the Bramble
  Charm damages attackers instead of granting knockback resistance.
- **No door opening/breaking, no block breaking, no wall climbing**, so terrain always works as a defence.
- **Models and textures are generated by code** (`tools/models.mjs`, `tools/icons.mjs`); the build has no dependencies.

## Rules for changes

- Run `npm run validate` before every commit; add tests with every behaviour change.
- Never change `tools/uuids.json` (worlds use the ids to recognise upgrades). Bump `package.json` for each release
  and keep only the current `.mcaddon` in `dist/` (the repository root ignores `dist/`, so use `git add -f`).
- Stable script APIs only. Check API calls against the real type definitions, not memory.
- Say what was checked and how. Automated tests are not a game test.
